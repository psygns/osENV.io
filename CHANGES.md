# osenv: what changed

## 0.3.0 (released 2026-09-25)
The rc11 light confirmation runs on Linux and Windows passed both tasks with nothing High or Medium: Jev answered every call on both machines, and every rc11 fix that could be reached held. 0.3.0 is rc11 plus the fixes below from those runs, each tested on Linux (with the race detector) and on Windows.
- From the rc11 confirmation runs:
  - `acts` pages by stamp. An act is stamped when it arrives and written once Jev has answered, so the log can hold two acts out of stamp order. A page cut in log order skipped one of them.
  - SKILL.md: word an owner rule's detect narrowly. A folder rule that gave `/tmp` as an example blocked a hybrid writing into its own temp folder.
  - README: each action is checked against every lesson (up to 128). Reviewers' actions are checked against the owner rules only.

## 0.3.0-rc11
- From the light rc10 confirmation run (rc11):
  - (rc11) Jev calls survive a stuck connection. On Windows every Jev call shared one HTTP/2 connection. When it went silent, each call waited out its 70-second timeout and retried on the same connection. For ten minutes nothing was judged: muse's actions ran unscored and its next run started late. The whole time, a fresh connection from the same VM answered in 0.4 s. Jev calls now go over HTTP/1.1 keep-alive, still at most 2 at a time, so a stuck connection holds only its own call. It is dropped when that call times out (30 s), and after any failure the retry starts on a fresh connection. Measured on the real Jev: 110 ms a call, and 214 real actions replayed in 18 s, as before. A first try cloned Go's default transport, which still offered HTTP/2 in the handshake, and Jev's front end dropped every request. The test now keeps osenv's own TLS setup and catches that.
  - (rc11) The desk hears it, once, when Jev stops answering ("the hybrids' actions run unscored until it answers again") and once when it answers again. `status` answers within 8 s even when Jev doesn't, and says so; it used to hang behind the stuck connection.
  - (rc11) A stop by a PID put in a variable in the same command (`P=12345; kill $P`) is a typed PID too. A PID read from a pidfile (`P=$(cat x.pid)`) isn't.
  - (rc11) A hand-fed action (`hook pre --test`) for a task that isn't live says "nothing was judged". It used to return nothing, which reads as allowed. A denied act keeps its reason in `acts`, as an allowed one keeps its note.

## 0.3.0-rc10
- From the light rc9 confirmation run on both machines (rc10):
  - (rc10) A process stopped by a PID typed as a number is denied, with how to keep one. On Windows muse read 12452 off a `Get-Process` listing and stopped it. The kill question scored 0.25 and let it through, because Jev never sees a listing's output and a typed number looks like a saved one. A wording that named listings scored the same case 0.23 to 0.30, so this is a rule. `kill -0` (a liveness check) and PIDs from a variable or pidfile (`$p.Id`, `$(cat x.pid)`) are untouched. In the rc8 and rc9 logs, the rule would have denied the bad stop, plus three rc8 stops of muse's own PID typed by hand, before the brief said how to keep one.
  - (rc10) A known mistake leads the note, surest first, with its score: "KNOWN MISTAKE IN THIS ACTION: ... (lesson L72, 0.92)". A write of project code that has one goes back once, and the next try goes through. On Linux, L72 (0.92) and L71 (0.87) caught real bugs in muse's first write. The note led with a lesson at 0.76 that didn't apply, and muse carried on with both bugs; it acts on a send-back, not on a note. Replaying all 80 project-code writes of the rc8 and rc9 runs against the pack, the rule would have sent back 3, all real catches (a test rewritten to check only that files exist; nan, the port range and float money in ledger.py), and nothing else. Its own task folder and commands keep the note.
  - (rc10) Acts get unique, increasing stamps. On Windows the clock steps in 100 ns, two parallel calls shared one stamp, and paging lost one of 120.
  - (rc10) KISS sends an action back at a "simpler" score of 0.7, the audit check's bar; it was 0.6. On Linux a kick at 0.60 pushed muse off its lesson's own practice (a before-and-after window list) onto a title search, and 0.3 to 0.7 is where Jev is unsure. No action in either rc9 run scored 0.7.
  - (rc10) "Does not serve the task" is recorded for the desk but not shown to muse. Its note was wrong 8 times out of 8 across the rc8 and rc9 runs. Clearing its own `$TMPDIR` scratch no longer draws "could be destructive" either.
  - (rc10) Two pack detects are sharper, measured on the real Jev:
    - L56 (check the port is free): it scored 0.77 to 0.80 on server code, which would now be sent back. It now scores 0.19 on code, 0.34 on a health check, and 0.87 on a real start with no check.
    - L85 (money in Decimal): it caught `round()` but missed float sums (0.21). Float sums now score 0.93, `round()` on a float 0.94, and Decimal 0.10.

## 0.3.0-rc9
- From the light rc8 confirmation run on both machines (rc9):
  - (rc9) Every lesson is checked on muse's and Opus's actions: up to 128 per action, where it was 16. Imported lessons all start with no track record, so the 16 went by ID. On Windows every action was checked against L1 to L9 of 84, and L71, which names the bug muse wrote (a bare `float()` letting nan through), was never checked. A Jev call's state is billed once, and its questions cost almost nothing. Past 128, the lessons closest to the action come first.
  - (rc9) Jev sees a whole write, up to 8000 characters. It used to see 600, and the bare `float()` sat at character 2836 of a 6 KB file. Measured on the real Jev: L71 scored 0.29 to 0.34 at 600 characters and 0.82 on the whole file; the fixed file scored 0.05 to 0.14.
  - (rc9) Reviewers (deepseek, qwen) are checked against the owner rules only. Lessons are learned from muse's work. Replaying both rc8 runs on the real Jev, all 7 lesson hits on reviewer actions were false alarms.
  - (rc9) Four pack lessons that raised false alarms have sharper detects. Each was measured on all 191 muse actions of both rc8 runs, plus a made-up action with each mistake:
    - L14 (a code review must say what it ran): false alarms went from 18 to 0, and it still catches the mistake (0.84).
    - L51 (a gate that only checks files exist): false alarms went from 7 to 1. The 1 is a real catch: muse rewriting the desk's test into an exists-only check.
    - L69 (polling that starts a process on every pass): false alarms went from 5 to 0, and it now catches the mistake (0.84, was 0.66).
    - L71 (float without isfinite): 0.82 on the bug.
  - (rc9) The pack adds the money-rounding lesson both machines' reviewers found: round() on a float turned 2.675 into 2.67. It scores 0.90 on the mistake with no false alarms. The pack now has 85 lessons.
  - (rc9) The kill check names searches. A PID taken from `ps | grep "<its own script> <its args>"` was allowed at 0.47 and denied at 0.52, eighteen seconds apart. The old wording allowed "a command line unique to your own run", and the desk's own copy of that script would have matched. Measured on the real Jev:
    - kills by a search: 0.66 to 0.95
    - kills by a saved PID, `$!`, `Start-Process -PassThru` or a window ID: 0.03 to 0.09
    - a kill by pidfile followed by a listing: 0.34 to 0.41 (0.50 before)

    The deny says how to save a PID on each OS. The Linux brief says how to keep one when the shell tool ends background jobs: `setsid -f sh -c 'echo $$ > "$TMPDIR/<name>.pid"; exec <command>'`.
  - (rc9) A park hold on a file that no action of the task wrote goes to the desk at once. On Windows the probe's file, written by the desk, was held and sent to muse, and muse rewrote the desk's test into one of its own.
  - (rc9) `status` counts hook calls for the server's whole life. It summed only the live tasks' counts, so once both tasks retired it said "no hook call seen yet" after 293 calls. rc8's retire cleanup caused this.
  - (rc9) Path facts leave out the program a command runs and, off Windows, any token with a backslash. The osenv binary's own path put the owner rule at 0.54 on a STEP DONE post, and a grep pattern, `\.osenv\`, was reported to Jev as a path outside the project.
  - (rc9) Acts are stamped to the nanosecond and paged by time, so paging with `before` no longer drops acts that share the boundary second (139 of 140 came back).
  - (rc9) `key=@file` drops the closing line break too. PowerShell's Set-Content adds a CRLF, and an owner rule kept it in its text.
  - (rc9) `proof mutate`'s transcript records the command with its flags, so pasting it back runs the same gate.
  - Measured and not changed: intake's "same mistake" question. A reviewer's restatement of L71 scored 0.62 to 0.68, under the 0.7 bar, so it was filed as a new lesson. A looser wording or a lower bar would also merge different lessons: a free-port check and "never kill a process you didn't start" scored 0.68. A duplicate lesson is the safer failure.
  - Not changed: a muse run that ends by asking the desk a question isn't parked, because the brief tells muse to ask and carry on. The park-hold routing above removes the case that cost a run.

- From the Tetris bench (three hybrids at once on one project, a kill -9 and two restarts mid-run, a spec change mid-build, a refactor undone while another hybrid kept writing):
  - Undo attributes by writes, over the whole run window. A file counts as touched by another hybrid only if one of its actions wrote it (a file tool on it, or a command that redirects into it or names it after rm, mv, tee, touch, sed -i, Set-Content and the like); a read that names it doesn't count. On the bench, another hybrid's `md5sum tetris/board.py` blocked undoing the run's own refactor of board.py. Undo also reads the whole action log for the run's window; it used to read only the last 200 actions, so after a busy stretch it could have undone another hybrid's files. And when other hybrids worked during the run, a change counts as the run's own only if one of its own actions wrote the file: a file some script wrote names no action, and is left alone (force=true to undo it anyway). On the bench the undo put board.py and test_board.py back byte for byte, and left the other hybrid's new tool alone.
  - The server refuses every desk verb from inside an engine run (verdicts, new tasks, pause, resume, cancel, undo, lesson retire, edit and import, owner rules, takes), batches included. Before, it refused only the take verbs, and only at the top level: a hybrid could have wrapped `take.list` in a batch. The hook still denies the same commands before they run.
  - `proof mutate --allow N`: a job may allow a few survivors (an equivalent mutant can't be caught); within the allowance the result is PASS and every survivor is still listed to explain. Before, any survivor read FAILED in `proof check` even when the job's gate was met.
  - A hybrid writing its own NOTES.md never gets a "there's a tool for that" note; a note that mentioned the tool got one.
  - `task.undo dry=true` says what it would restore, delete and leave alone, and touches nothing.
  - A run that outlives its server (a crash) gets its undo record closed when it ends, and a run stopped with the server gets it closed at the next start, so both can be undone.
